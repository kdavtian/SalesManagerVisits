## Lists (hidden)
A2:A5 = Distributor, Factory, Official Service, Company; B2:B5 = Castrol, Lotos, Royal, Orlen. The supplier-type to brand legend (Castrol is the distributor relationship; Lotos is bought from the factory; Royal = official service source; Orlen = company). Not read by any code.

## Purchase_IN (supplier invoices) - table `IN`
Row 1 = totals/parameters: `J1` total USD, `K1` **USD->AMD rate used here (385)**, `L1` total AMD, `M1` liters. Columns: `No`, `InvoiceID` (int or text like `KAL 1/24`), `Date`, `Supplier` (GT Group, Sole Trans -> Castrol; Luk Oil -> Royal; Orlen Oil -> Lotos & Orlen), `ProductID` (= Brand&Product_Name&Size), `Brand`, `Product_Name`, `Size` (L per pack), `QTY` (packs), `Cost USD` (unit price, USD per pack), `SUM` = Cost USD x QTY, `Cost AMD` = Cost USD x $K$1, `SUM AMD`, `Liter` = Size x QTY, `Order Amount` (rare, planned order value), `Info` (free text: "Total: 8441.08$ Paid: 8441.08$" - payment reconciliation notes). 438 rows, 2023-11-30 -> 2026-09-17. Feeds Inventory `IN` via `SUMIFS(IN[QTY], IN[ProductID], id, IN[Date], "<=" & Inventory!C1)` and the "first purchase date" in sales velocity.

## Products (master data + landed-cost model) - table `Products`
Row 1 holds the **cost-model parameters** (each sits above the column that uses it): `A1` USD rate 377.5, `O1` 0.35 (legal transport USD/kg for brands other than Castrol/Lotos), `Q1` 0.02 (ecology rate), `R1` 0.05 (customs rate), `S1` 682 (excise AMD/kg netto), `T1` 0.20 (VAT), `U1` customs handling = (88000+44000+25000)/A1/25000 (USD per liter), `Z1` 0.04 (manager-salary % of price), `AA1` 0.18 (profit tax). Row 2 = column numbers 0..35 (helper for VLOOKUP col indexes). 246 products (incl. a `Brand=Test` row, "TestProduct 208L", to ignore).

Columns (A..AK): `No`; `ProductID` (formula Brand&Product_Name&Size L); `SKU` (Castrol 6-char codes, 125 filled); `HC_ID` (accounting program ՀԾ-Հաշվապահ product code, text with leading zeros e.g. `000010`, 146 filled - used by the Lily accountant & synced to the app as `hc_code`); `GTIN`; `Product Global Name` (Castrol's own catalogue name); `Brand`; `Product_Name`; `Size L`; `Items per Pack`; `Pack Netto kg`; `Netto` = Pack Netto / Items per Pack (kg per unit); `Pack Cost USD` (typed, supplier price per pack); `Cost USD` = Pack Cost / Items; **cost chain**: `Transportation Legal` (Castrol: Netto x 2007/9280; Lotos: Netto x 0.35; else Netto x O1), `Transport Real` = 0.252 x Netto, `Ecology` = (Cost+TransportLegal) x 2%, `Customs` = (Cost+TransportLegal) x 5%, `Excise tax` = Netto x 682 / USD rate, `VAT` = (Cost+TransportLegal+Customs+Excise) x 20%, `Customs Costs` = U1 x Size L, `Other Costs` (empty); `Landing Cost USD` = SUM(Cost USD : Other Costs) (note: includes Transport Real); `Landing Cost AMD` = USD x 377.5; `Landing cost Per Lt`; `% of Manager's Salary` = 4% x **Price T1 Bronze** (VLOOKUP col 6 of PriceList - see gotchas), `Profit Tax` = max(0, (Bronze - Landing AMD + Transport Real x A1) x 18%); `VAT tax`, `Other VC`, `Other FC` (empty); **`Net Cost AMD`** = Landing Cost AMD + manager % + profit tax + the empty columns; then the typed commercial prices `Price T1 Bronze`, `Price T2 Silver`, `Price T3 Gold`, `Retail Price` (AMD per pack/unit); `Product Family` (Edge/Magnatec/GTX for 76 Castrol rows only); `Show` (empty).
Coverage: HC_ID Castrol 66/146, Lotos 19/34, Orlen 2/4, Royal 59/61. Bronze typed for only 147 of 246 products; silver 236, gold 239, retail 239.

## PriceList (view) - table `Pricelist`
Pure VLOOKUP into Products by ProductID: `Landing Cost` (Products col 23), `Price T1 Bronze/T2 Silver/T3 Gold/Retail Price` (cols 31-34), `Net Cost` (col 30), plus computed `Profit per L` = (Bronze - NetCost)/Size, `Margin` = (Bronze - NetCost)/Bronze, `Discount` = (Retail - Bronze)/Retail. **Empty source cell -> 0** (so bronze 0 = no bronze price); `Margin`/`Discount` become `#DIV/0!` for those rows (99 / 111). 247 rows for 245 distinct ProductIDs (two Castrol CRB Tmax 15w40 rows are duplicated - last one wins in the bot). Rows 250-363 are formatting leftovers, empty. The bot's `build_products` reads this sheet (+ Products sheet for HC_ID/Net Cost AMD).

## Inventory - table `Inventory`
Parameters row 1: `C1` = `TODAY()`, `D1` text "Order: $..." (value of the draft purchase order at /370), subtotals above columns. Columns: `ProductID`, `Brand`, `Product_Name`, `Size`, `OB` (opening balance, 50 rows, sum 5709 packs), `IN` = SUMIFS purchases up to C1, `OUT` = SUMIFS(Orders[Qty]) up to C1 (includes customer 10000 internal movements), `Order` (draft purchase qty, empty), `QTY` = OB + IN - OUT + Order (stock in packs), `Actual`/`Diff` (physical count, unused), `Liter` = Size x QTY, `Cost` = landing cost (VLOOKUP PriceList col 5), `Price T2` = **silver** price (PriceList col 7), `Monthly Sales Volume (Liter)` = 30 x SUMIFS(Orders[Qty] for this product, Customer ID <> 10000) / (TODAY() - first purchase date of the product, default serial 45658 = 2025-01-01 if never purchased) x Size - i.e. **all-time average**, not recent; `Days` = Liter / Monthly Volume x 30 (days of cover; blank if no sales; can be hugely negative/positive when returns make volume ~0 or negative), `SKU`, `Order Packs`. Stock valuation = SUMPRODUCT(Cost, QTY).

## Customers - table `Customers`
`Customer ID` (10000.., unique), `Customer Name` (short/trade), `Legal Name`, **`Tier`** (new in 2.0.7: Gold/Silver - currently 5 Gold incl. the internal 10000 and 411 Silver; no Bronze/Potential), **`Assigned To`** (sales channel code: KF, CAS, OEM, PCO, CVO, SM YVN, SM Shirak, SM Davtashen, SM B2B, SM CAS; 27 blank), `TIN` (tax id, 237 filled), `Contacts & info`, `Phone Number`, `Region`/`Subregion` (English marz/city names; used for app autofill), `Address`, `Total Revenue` = SUMIFS(Orders[Total], Customer ID), `Total Paid` = SUMIFS(Cash[Amount], Cash[ID], id) (note: sums EVERY cash row with that ID in original currency, not only "Oil order"), `Debit Balance` = Revenue - Paid + Balance0, `Balance0` (opening debt carried from before the ledger; typed; 75 non-zero), `Partner Since` = date of the customer's first order row (0/time when none).

## Debits - table `Debit` (live AR per customer)
Row 1: `A1` label "Month"; **`A2` is a month filter: blank = all-time (live debt); a date = orders/payments of that month only** (the bot always reads it blank). Columns: `Customer ID`, `Customer Name` (VLOOKUP col 2), **`Assigned To` (VLOOKUP col 4 of Customers[[Customer ID]:[Assigned To]] - after Tier was inserted this returns the TIER, see gotchas)**, `Order` (sum of Orders.Total), `Paid` (sum Cash.Amount by ID), `Debit` = Balance0 + Order - Paid, `Diff` = Paid - Order, `Balance0`, `Last Payment` = MAXIFS(Cash[Date], Cash[ID], id), `Last Order` = MAXIFS(Orders[Date]...), `Risk` (rules below), `Due Days` = TODAY() - Last Payment (blank if none).
Risk: Debit < 1 -> "No Debt"; else High if Due Days > 60, or Diff < -500,000, or Debit/Order > 0.2; Medium if Due Days > 30, Diff < -250,000 or Debit/Order > 0.1; else Low. (`Debit/Order` raises #DIV/0! when a customer has debt but no orders - Balance0-only customers.)

## ORDERS - table `Orders` (one row per product line; 6054 rows, 2028 orders)
`Order ID` int `YYMMDDnn` (nn = running number that day, max 15), `Date` = formula from the ID, `Customer ID`, `Company Name` (VLOOKUP), `Tier` (VLOOKUP Customers col 4 - the customer's CURRENT tier, not the tier price used), `ProductID` (formula), `Brand`, `Product_Name`, `Size L`, `Qty` (negative = return), `UnitPrice` (typed, AMD, the list/negotiated price), `Discount` (typed per UNIT: negative = discount, positive = price add/surcharge; blank = none), `Total` = Qty x (UnitPrice + Discount), `Order Amount` (typed on one line per order: the invoice/payment total used as a control; matches the sum of Totals in 1979 of 1980 orders), `Sales_Rep` (the selling channel code), `Payment Method` (Cash 1289 / Invoice 690 / Free 1 orders; blank for the early-2025 aggregate rows), `Total Liter` = Size x Qty, `Comment` (free text, mostly gifts/car models/returns "brak"). Header cell for the totals row 1: `L1` = sum(Qty x Discount) + 235,683,700 (a manual adjustment constant), `M1` total sales.

## Cashflow - table `Cash` (header row 9; rows 1-8 = control panel)
Control panel (A1:R8): `A1` = report month date (drives the month-to-date boxes), `B..` balances per source: Cash AMD/USD, Cash Gevorg/YVN/DVT/Shirak (per-rep cash boxes), EvocaBank/ABB Bank AMD+USD, Evoca Credit Line, ArmSwiss, Varki Gumar; `L1` USD rate 380; category tables (columns F:R) with month and all-time totals per `For` category (Oil Order / Marketing / Dividend groups).
Ledger columns: `Date`, `Amount` (signed, original currency), `Currency` (AMD/USD), **`For`** (category: `Oil order` = customer payment received; expenses: Purchase, Customs, Tax, Transportation, Salary, Office, Fuel, Maintenance, Marketing, Loan, Interest, PPE, Other; owner/equity: Divident, Personal, Armen Loans, Investment; internal: To bank, Exchange, Transfer, Balance, Credit Line, Poxarutyun, Veradarcvox), `ID` (Customer ID for Oil order rows; for expense rows free text such as a car plate/model), `Source` (which pot of money: Cash, Cash YVN/DVT/Shirak/Gevorg/Slav, EvocaBank AMD/USD, ABB Bank, ArmSwiss, Varki Gumar, Evoca Credit Line), `Info`, `Customer_Name` (VLOOKUP), `Currency Rate` (typed on USD rows, 360-392), `Amount AMD` = Amount if AMD else Amount x rate, `Sales Rep` (channel for Oil-order rows; one legacy "Marat" appears), `TransactionID`. Customer payments: `For="Oil order"` with numeric `ID`; 80 early rows have blank ID (Info "Slav/ Castrol" - distributor settlements), positive amounts; one negative = refund. Many operations are **paired lines** (an incoming Oil order and a matching Purchase outflow for pass-through settlements, bank<->cash transfers, exchanges).

## Orders_P (stale pivot)
A cached pivot "Sum of Total": Years x Months and Channel x Month, last refreshed mid-2026. **Do not read numbers from it** (it also shows the bogus "Silver"/"Gold" channel rows caused by the Sales_Rep data-entry slip).

## Tabel (monthly payroll blocks) - CONFIDENTIAL content
One block per month (Jun-2025 .. Oct-2026): date row, header `Position, Name, Fixed salary, Fix bank, Revenue, New Clients, Days, Amount, Paid Cash, To Pay, Info`, one row per staff position, TOTAL row. Formulas: `Revenue` = collections (Cash "Oil order") of that month for the position's Sales Rep; `New Clients` = COUNTIFS(Customers Assigned To = position, Partner Since within the month); `Amount` = ROUNDUP(fixed + 2% x Revenue [+ 30,000 x New Clients for the CAS manager], -3); `Paid Cash` = SUMPRODUCT of Cash rows `For="Salary"` whose `Info` = "<Position> <YYYY> <MON>" (negative); `To Pay` = Amount + Paid. Positions: Director, Sales Director, Sales Managers by channel, Financial Director, Accountant, Warehouse Manager, Shipping Manager. Never reproduce names/amounts.

## Sales Team_2026 (KPI bonus engine, per rep block)
One block per rep/channel (Sales Director, SM YVN, SM Shirak, SM CAS, SM B2B, SM Davtashen), columns C..N = Jan..Dec 2026, O = Total. Rows: `Sales` = SUMPRODUCT Orders.Total for the month (Sales Director = all sales minus the channels listed in the formula), `Collected` = Cash Oil-order Amount AMD for the rep's channel, `Budget` = Collected x 2% (bonus pool), `KPI1.x_Performance_Castrol/Lotos/Royal` = actual/plan liters from Plan_2026 (weights 45%/30%/25%), `KPI1.1-1.3` payout tiers (>120% x130%, >100% x115%, >90% x100%, >75-80% x90%, else 0), `KPI2_Performance` = Collected/Sales (collection ratio; >100% x120%, >90% x100%, >75-80% x90%), `KPI3_Performance` = new customers (Partner Since in the month; thresholds >11/>25 etc.), `Total` = MAX(sum of KPI payouts, Collected x 2%), last row = Total + fixed base (400,000 director / 180,000 managers). The bot reads `Sales`/`Collected`/`Budget` rows per channel for `sales_performance` (falls back to ORDERS/Cashflow when a Sales cell is an Excel error). Several cells are `#VALUE!`/`#DIV/0!` (Total 2026 column, months with no sales); B2B block uses odd thresholds (147%).

## Plan_2026 (liters plan vs actual)
Rows per channel (SM B2B, SM YVN, SM Davtashen, SM Shirak, SM Syunik, SM CAS, CAS, PCO, CVO, OEM, KF; some "SM YVN3/4" placeholders) x brand (Castrol, Lotos, Royal, Clients); for each month a triplet `Plan | Actual | KPI %` (columns C.. step 3 for 2026-01..12; Total 2026 at AN:AO). `Actual` = SUMPRODUCT(Orders[Total Liter] by month, Brand, Sales_Rep). Row 4-7 = Sales Director aggregate; rows 60-63 TOTAL. Plan is in **liters**; the app's own plan feature (AMD sales plan) is separate.

## KPI_2025 (hidden legacy)
Per-person liters by brand, 2025 months (same SUMPRODUCT pattern). Superseded by Sales Team_2026/Plan_2026.
