## What changed in 2.1.0 (vs 2.0.8) - read this first
Verified with `scripts/dump_formulas.py` (formula patterns per column) and cached values:
1. **Net cost model rewritten (Products `Z`..`AE`)** - now Landing + 4% x Bronze + 20% "VAT tax" + 18% "Profit Tax" (both on the SILVER margin) + 790 AMD x Size "Other FC". The new `AA`/`AB` formulas subtract `Landing cost Per Lt` (per LITER) from the Silver price (per PACK), so for packs > 1 L net cost is overstated (median +18 %); for 4 L and drums it exceeds the silver price (106 of 172 active products). Details + fix in business-and-finance.md section 2 and data-quality A1.
2. **`PriceList` `Profit per L` / `Margin` / `Discount` now use SILVER** (they used Bronze in 2.0.7); bronze is now filled for 245 of 246 products (was ~60 %), so "bronze empty -> silver" matters for one product only (`CastrolStend`, no prices at all).
3. **`Debits[Assigned To]` fixed** (VLOOKUP index 5 = channel again), but `Debits[Last Payment]`/`[Last Order]` are `#NAME?` in all 415 rows (MAXIFS unsupported by the app that last saved the file) -> `Due Days` blank -> `Risk` = "High" for every debtor. Recalculate in desktop Excel 2019/365 or replace MAXIFS (see data-quality A2).
4. **ORDERS**: `Sales_Rep` no longer contains Silver/Gold (0 rows; 117 newest rows are a formula = customer's `Assigned To`); `UnitPrice` is a formula (tier price lookup by the customer's `Tier`) on 128 lines since 2025-10; `Order Amount` control now matches the order total for ALL orders; 6,181 lines / 2,057 orders, last order 2026-10-08.
5. **Cashflow**: `Source` is a formula on 463 rows (Oil-order cash receipts go to the rep's cash box by `Sales Rep`: SM YVN -> Cash YVN, SM Davtashen -> Cash DVT, SM Shirak -> Cash Shirak, else Cash); `Currency`/`For` are formulas ("AMD"/"Oil order") on some rows; `Sales Rep` is a formula (customer's channel) on 90 rows; control-panel month `A1` is current (2026-10-01).
6. `Customers[Tier]` has a dropdown again with **Bronze/Silver/Gold** (data still only Silver 411 / Gold 5).
7. Still true: `Sales Team_2026` Total 2026 column `#VALUE!`; `Plan_2026` SM B2B actual rows point at the SM Shirak label (see Plan_2026 below); Tabel runs Jun-2025..Oct-2026.

The bot's constants (build_ceo_report.py): `ORDERS_HEADER_ROW`, `CASHFLOW_HEADER_ROW`, `PRICELIST_HEADER_ROW=2`, `DEBITS_HEADER_ROW`, `INVENTORY_HEADER_ROW`; sync_field_visits: `PRODUCTS_HEADER_ROW=3`, `CUSTOMERS_HEADER_ROW=2`. Keep them equal to the table above.

## Lists (hidden)
A2:A5 = Distributor, Factory, Official Service, Company; B2:B5 = Castrol, Lotos, Royal, Orlen. The supplier-type to brand legend (Castrol is the distributor relationship; Lotos is bought from the factory; Royal = official service source; Orlen = company). Not read by any code.

## Purchase_IN (supplier invoices) - table `IN`
Row 1 = totals/parameters: `J1` total USD, `K1` **USD->AMD rate used here (385)**, `L1` total AMD, `M1` liters. Columns: `No`, `InvoiceID` (int or text like `KAL 1/24`), `Date`, `Supplier` (GT Group, Sole Trans -> Castrol; Luk Oil -> Royal; Orlen Oil -> Lotos & Orlen), `ProductID` (= Brand&Product_Name&Size), `Brand`, `Product_Name`, `Size` (L per pack), `QTY` (packs), `Cost USD` (unit price, USD per pack), `SUM` = Cost USD x QTY, `Cost AMD` = Cost USD x $K$1, `SUM AMD`, `Liter` = Size x QTY, `Order Amount` (rare, planned order value), `Info` (free text: "Total: 8441.08$ Paid: 8441.08$" - payment reconciliation notes). 438 rows, 2023-11-30 -> 2026-09-17. Feeds Inventory `IN` via `SUMIFS(IN[QTY], IN[ProductID], id, IN[Date], "<=" & Inventory!C1)` and the "first purchase date" in sales velocity.

## Products (master data + landed-cost model) - table `Products`
Row 1 holds the **cost-model parameters** (each sits above the column that uses it): `A1` USD rate 377.5, `O1` 0.35 (legal transport USD/kg for brands other than Castrol/Lotos), `Q1` 0.02 (ecology rate), `R1` 0.05 (customs rate), `S1` 682 (excise AMD/kg netto), `T1` 0.20 (VAT), `U1` customs handling = (88000+44000+25000)/A1/25000 (USD per liter), `Z1` 0.04 (manager-salary % of price), `AA1` 0.18 (profit tax), **`AB1` 0.20 (VAT on margin), `AD1` 790 (fixed cost AMD per liter) - new in 2.1.0**. Row 2 = column numbers 0..35 (helper for VLOOKUP col indexes). 246 products (incl. a `Brand=Test` row, "TestProduct 208L", to ignore).

Columns (A..AK): `No`; `ProductID` (formula Brand&Product_Name&Size L); `SKU` (Castrol 6-char codes, 125 filled); `HC_ID` (accounting program ՀԾ-Հաշվապահ product code, text with leading zeros e.g. `000010`, 146 filled - used by the Lily accountant & synced to the app as `hc_code`); `GTIN`; `Product Global Name` (Castrol's own catalogue name); `Brand`; `Product_Name`; `Size L`; `Items per Pack`; `Pack Netto kg`; `Netto` = Pack Netto / Items per Pack (kg per unit); `Pack Cost USD` (typed, supplier price per pack); `Cost USD` = Pack Cost / Items; **cost chain**: `Transportation Legal` (Castrol: Netto x 2007/9280; Lotos: Netto x 0.35; else Netto x O1), `Transport Real` = 0.252 x Netto, `Ecology` = (Cost+TransportLegal) x 2%, `Customs` = (Cost+TransportLegal) x 5%, `Excise tax` = Netto x 682 / USD rate, `VAT` = (Cost+TransportLegal+Customs+Excise) x 20%, `Customs Costs` = U1 x Size L, `Other Costs` (empty); `Landing Cost USD` = SUM(Cost USD : Other Costs) (note: includes Transport Real); `Landing Cost AMD` = USD x 377.5; `Landing cost Per Lt`; `% of Manager's Salary` = 4% x **Price T1 Bronze** (VLOOKUP col 6 of PriceList); **2.1.0:** `Profit Tax` (AA) = (Price T2 **Silver** - **Landing cost Per Lt** - VAT tax) x 18%; `VAT tax` (AB) = (Silver - **Landing cost Per Lt**) x 20%; `Other VC` (empty); `Other FC` (AD) = Size L x 790; **`Net Cost AMD`** (AE) = Landing Cost AMD + manager % + Profit Tax + VAT tax + Other VC + Other FC (no max(0,...): profit tax can go negative - 8 active rows). **Unit bug:** AA/AB subtract a per-liter cost from a per-pack price, right only for 1 L packs; then the typed commercial prices `Price T1 Bronze`, `Price T2 Silver`, `Price T3 Gold`, `Retail Price` (AMD per pack/unit); `Product Family` (**2.0.8: filled for every product** - product lines Edge, Magnatec, GTX, CRB, Vecton, ON and categories Engine Oil, Transmission, Hydraulic, Antifreeze, Grease, Other); `SKU Status` (**2.0.8, replaced the empty `Show` column**: `Active` = currently sold - 172 of 245 rows; blank = not sold). The app/bot keep only ACTIVE products everywhere (inventory, new orders, pricelist, products page).
Coverage (2.1.0): HC_ID 152 of 246 rows, SKU 125; Bronze and Silver typed for 245 of 246 (all but `CastrolStend`), Gold ~225, Retail ~149 (PriceList rows); `SKU Status` Active 173. Product Family now 13 values incl. `Merch` (1 row).

## PriceList (view) - table `Pricelist`
Pure VLOOKUP into Products by ProductID: `Landing Cost` (Products col 23), `Price T1 Bronze/T2 Silver/T3 Gold/Retail Price` (cols 31-34), `Net Cost` (col 30), plus computed (2.1.0: all on the **Silver** price) `Profit per L` = Silver/Size - NetCost/Size, `Margin` = (Silver - NetCost)/Silver, `Discount` = (Retail - Silver)/Retail. **Empty source cell -> 0** (so a 0 price = empty); `Margin` has 1 error cell, `Discount` 98 (rows without a retail price). 247 rows for 245 distinct ProductIDs (two Castrol CRB Tmax 15w40 rows are duplicated - last one wins in the bot). Rows 250-363 are formatting leftovers, empty. The bot's `build_products` reads this sheet (+ Products sheet for HC_ID/Net Cost AMD).

## Inventory - table `Inventory`
Parameters row 1: `C1` = `TODAY()`, `D1` text "Order: $..." (value of the draft purchase order at /370), subtotals above columns. Columns: `ProductID`, `Brand`, `Product_Name`, `Size`, `OB` (opening balance, 50 rows, sum 5709 packs), `IN` = SUMIFS purchases up to C1, `OUT` = SUMIFS(Orders[Qty]) up to C1 (includes customer 10000 internal movements), `Order` (draft purchase qty, empty), `QTY` = OB + IN - OUT + Order (stock in packs), `Actual`/`Diff` (physical count, unused), `Liter` = Size x QTY, `Cost` = landing cost (VLOOKUP PriceList col 5), `Price T2` = **silver** price (PriceList col 7), `Monthly Sales Volume (Liter)` = 30 x SUMIFS(Orders[Qty] for this product, Customer ID <> 10000) / (TODAY() - first purchase date of the product, default serial 45658 = 2025-01-01 if never purchased) x Size - i.e. **all-time average**, not recent; `Days` = Liter / Monthly Volume x 30 (days of cover; blank if no sales; can be hugely negative/positive when returns make volume ~0 or negative), `SKU`, `Order Packs`. Stock valuation = SUMPRODUCT(Cost, QTY).

## Customers - table `Customers`
`Customer ID` (10000.., unique), `Customer Name` (short/trade), `Legal Name`, **`Tier`** (2.0.7+: dropdown Bronze/Silver/Gold; data today 5 Gold incl. the internal 10000 and 411 Silver, no Bronze/Potential), **`Assigned To`** (sales channel code: KF, CAS, OEM, PCO, CVO, SM YVN, SM Shirak, SM Davtashen, SM B2B, SM CAS; 24 blank, all among the newest IDs 10370+), `TIN` (tax id, 237 filled), `Contacts & info`, `Phone Number`, `Region`/`Subregion` (English marz/city names; used for app autofill), `Address`, `Total Revenue` = SUMIFS(Orders[Total], Customer ID), `Total Paid` = SUMIFS(Cash[Amount], Cash[ID], id) (note: sums EVERY cash row with that ID in original currency, not only "Oil order"), `Debit Balance` = Revenue - Paid + Balance0, `Balance0` (opening debt carried from before the ledger; typed; 75 non-zero), `Partner Since` = date of the customer's first order row (0/time when none: 149 customers). One duplicated ID: **10408** appears twice (second row has no name).

## Debits - table `Debit` (live AR per customer)
Row 1: `A1` label "Month"; **`A2` is a month filter: blank = all-time (live debt); a date = orders/payments of that month only** (the bot always reads it blank). Columns: `Customer ID`, `Customer Name` (VLOOKUP col 2), **`Assigned To` (VLOOKUP col 5 of Customers[[Customer ID]:[Assigned To]] - fixed in 2.1.0; returns 0 for the 24 customers with no channel)**, `Order` (sum of Orders.Total), `Paid` (sum Cash.Amount by ID), `Debit` = Balance0 + Order - Paid, `Diff` = Paid - Order, `Balance0`, `Last Payment` = MAXIFS(Cash[Date], Cash[ID], id), `Last Order` = MAXIFS(Orders[Date]...) (**2.1.0 file: `#NAME?` on every row**, so `Due Days` is blank and every debtor is `High`; the bot takes last payment from Cashflow instead), `Risk` (rules below), `Due Days` = TODAY() - Last Payment (blank if none). Conditional formats highlight rows where `Diff` <= -500,000 and where `Diff` < -50,000. Totals row 2 (`D2:H2`) = SUBTOTAL of Order/Paid/Debit/Diff/Balance0: debt 106.9M = 76.9M Balance0 + 488.4M orders - 458.4M paid.
Risk: Debit < 1 -> "No Debt"; else High if Due Days > 60, or Diff < -500,000, or Debit/Order > 0.2; Medium if Due Days > 30, Diff < -250,000 or Debit/Order > 0.1; else Low. (`Debit/Order` raises #DIV/0! when a customer has debt but no orders - Balance0-only customers.)

## ORDERS - table `Orders` (one row per product line; 6,181 rows, 2,057 orders in 2.1.0)
`Order ID` int `YYMMDDnn` (nn = running number that day, max 15), `Date` = formula from the ID, `Customer ID`, `Company Name` (VLOOKUP), `Tier` (VLOOKUP Customers col 4 - the customer's CURRENT tier, not the tier price used), `ProductID` (formula), `Brand`, `Product_Name`, `Size L`, `Qty` (negative = return), `UnitPrice` (typed AMD list/negotiated price; **since 2025-10-05 128 lines hold a formula**: `Tier` Bronze/Silver/Gold -> `VLOOKUP` of Pricelist col 6/7/8, i.e. the customer's CURRENT tier price, 0 for other tiers), `Discount` (typed per UNIT: negative = discount, positive = price add/surcharge; blank = none), `Total` = Qty x (UnitPrice + Discount), `Order Amount` (typed on one line per order: the invoice/payment total used as a control; **in 2.1.0 it matches the sum of Totals for every order**; `N1` = 488,431,095 = `M1`), `Sales_Rep` (the selling channel code; the newest 117 rows are a formula = Customers `Assigned To`, so the 2.0.7 Silver/Gold slips are gone), `Payment Method` (dropdown Invoice/Cash/Free; 2.1.0 lines: Cash 2,950, Invoice 2,708, blank 522 = early-2025 aggregate rows, Free 1), `Total Liter` = Size x Qty, `Comment` (free text, mostly gifts/car models/returns "brak"). Header cell for the totals row 1: `L1` = sum(Qty x Discount) + 235,683,700 (a manual adjustment constant), `M1` total sales, `N1` sum of Order Amount, `Q1` total liters (215,767 L). A conditional format draws a separator when `Order ID` changes.

## Cashflow - table `Cash` (header row 9; rows 1-8 = control panel)
Control panel (A1:R8): `A1` = report month date (drives the month-to-date boxes; **2026-10-01 in 2.1.0**, was stale 2026-08 before), `B..` balances per source: Cash AMD/USD, Cash Gevorg/YVN/DVT/Shirak (per-rep cash boxes), EvocaBank/ABB Bank AMD+USD, Evoca Credit Line, ArmSwiss, Varki Gumar; `L1` USD rate 380; category tables (columns F:R) with month and all-time totals per `For` category (Oil Order / Marketing / Dividend groups).
Ledger columns: `Date`, `Amount` (signed, original currency), `Currency` (AMD/USD), **`For`** (category: `Oil order` = customer payment received; expenses: Purchase, Customs, Tax, Transportation, Salary, Office, Fuel, Maintenance, Marketing, Loan, Interest, PPE, Other; owner/equity: Divident, Personal, Armen Loans, Investment; internal: To bank, Exchange, Transfer, Balance, Credit Line, Poxarutyun, Veradarcvox), `ID` (Customer ID for Oil order rows; for expense rows free text such as a car plate/model), `Source` (**463 rows are a formula in 2.1.0**: Oil order + Sales Rep SM YVN -> `Cash YVN`, SM Davtashen -> `Cash DVT`, SM Shirak -> `Cash Shirak`, else `Cash`; other rows typed; **spelling variants `Evocabank AMD/USD` vs `EvocaBank AMD/USD`** - Excel treats them as equal, code must casefold) (which pot of money: Cash, Cash YVN/DVT/Shirak/Gevorg/Slav, EvocaBank AMD/USD, ABB Bank, ArmSwiss, Varki Gumar, Evoca Credit Line), `Info`, `Customer_Name` (VLOOKUP), `Currency Rate` (typed on USD rows, 360-392), `Amount AMD` = Amount if AMD else Amount x rate, `Sales Rep` (channel for Oil-order rows; one legacy "Marat" appears), `TransactionID`. Customer payments: `For="Oil order"` with numeric `ID`; 80 early rows have blank ID (Info "Slav/ Castrol" - distributor settlements), positive amounts; one negative = refund. Many operations are **paired lines** (an incoming Oil order and a matching Purchase outflow for pass-through settlements, bank<->cash transfers, exchanges).

## Orders_P (stale pivot)
A cached pivot "Sum of Total": Years x Months and Channel x Month, last refreshed mid-2026. **Do not read numbers from it** (it also shows the bogus "Silver"/"Gold" channel rows caused by the Sales_Rep data-entry slip).

## Tabel (monthly payroll blocks) - CONFIDENTIAL content
One block per month (Jun-2025 .. Oct-2026; rows 1, 10, 21, 32, 43, 54, 64, 75, 86, 98, 110, 122, 137, 151, 166, 181, 196): date row, header `Position, Name, Fixed salary, Fix bank, Revenue, New Clients, Days, Amount, Paid Cash, To Pay, Info`, one row per staff position, TOTAL row. Formulas: `Revenue` = collections (Cash "Oil order") of that month for the position's Sales Rep; `New Clients` = COUNTIFS(Customers Assigned To = position, Partner Since within the month); `Amount` = ROUNDUP(fixed + 2% x Revenue [+ 30,000 x New Clients for the CAS manager], -3); `Paid Cash` = SUMPRODUCT of Cash rows `For="Salary"` whose `Info` = "<Position> <YYYY> <MON>" (negative); `To Pay` = Amount + Paid. Positions: Director, Sales Director, Sales Manager YVN / YVN2 / CAS / Shirak / Davtashen / Syunik / B2B (earlier blocks use the channel names `SM YVN`, ...), Financial Director, Accountant, Warehouse Manager, Shipping Manager. `Revenue` sums `Cash[Amount]` (original currency) while Sales Team_2026 sums `Amount AMD`; the `Paid Cash` key is the text `<Position> <YYYY> <MON>` typed per block. Never reproduce names/amounts.

## Sales Team_2026 (KPI bonus engine, per rep block)
One block per rep/channel (Sales Director, SM YVN, SM Shirak, SM CAS, SM B2B, SM Davtashen), columns C..N = Jan..Dec 2026, O = Total. Rows: `Sales` = SUMPRODUCT Orders.Total for the month (Sales Director = all sales minus the channels listed in the formula), `Collected` = Cash Oil-order Amount AMD for the rep's channel, `Budget` = Collected x 2% (bonus pool), `KPI1.x_Performance_Castrol/Lotos/Royal` = actual/plan liters from Plan_2026 (weights 45%/30%/25%), `KPI1.1-1.3` payout tiers (>120% x130%, >100% x115%, >90% x100%, >75-80% x90%, else 0), `KPI2_Performance` = Collected/Sales (collection ratio; >100% x120%, >90% x100%, >75-80% x90%), `KPI3_Performance` = new customers (Partner Since in the month; thresholds >11/>25 etc.), `Total` = MAX(sum of KPI payouts, Collected x 2%), last row = Total + fixed base (400,000 director / 180,000 managers). The Sales Director block's `Sales`/`Collected` = ALL sales/receipts minus channels CAS and KF only (so it includes PCO, CVO, OEM, B2B and the SM channels). KPI weights differ per block (director 45/45/10 for KPI1/KPI2/KPI3, SM YVN 45/40/15, Shirak 35/40/15, SM CAS 35/30/35). Rows: director 1-17, SM YVN 20-35, Shirak 38-53, SM CAS 56-71, B2B 74-89, Davtashen 92-107; the last row of each block (no label) = payout incl. fixed base; the `Total 2026` column (O) is broken (its header is text, so MONTH() fails; O22 even holds `#REF!`). The bot reads `Sales`/`Collected`/`Budget` rows per channel for `sales_performance` (falls back to ORDERS/Cashflow when a Sales cell is an Excel error). Several cells are `#VALUE!`/`#DIV/0!` (Total 2026 column, months with no sales); B2B block uses odd thresholds (147%).

## Plan_2026 (liters plan vs actual)
Rows per channel (SM B2B, SM YVN, SM Davtashen, SM Shirak, SM Syunik, SM CAS, CAS, PCO, CVO, OEM, KF; some "SM YVN3/4" placeholders) x brand (Castrol, Lotos, Royal, Clients); for each month a triplet `Plan | Actual | KPI %` (columns C.. step 3 for 2026-01..12; Total 2026 at AN:AO). `Actual` = SUMPRODUCT(Orders[Total Liter] by month, Brand, Sales_Rep). Row 4-7 = Sales Director aggregate (= B2B + YVN + Shirak + Syunik + SM CAS + PCO + CVO + OEM, i.e. NOT CAS and KF); rows 60-63 TOTAL (all channels). Plan cells are typed constants; `Actual` formulas anchor the channel on the block's label cell (`$A$12`, ...). **Defect:** the SM B2B `Actual` cells in January (D8:D10) reference `$A$28` (the SM Shirak label), so B2B shows Shirak liters whenever they are non-zero (harmless in 2.1.0 because January Shirak = 0 - re-check on new files). Brands in the plan: Castrol, Lotos, Royal, Clients (Orlen has no plan row though ORDERS has 48 Orlen lines). Plan is in **liters**; the app's own plan feature (AMD sales plan) is separate.

## KPI_2025 (hidden legacy)
