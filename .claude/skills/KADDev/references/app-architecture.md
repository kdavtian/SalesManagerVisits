# Field Visits app - architecture map

Repo `kdavtian/SalesManagerVisits`. Production: one DigitalOcean droplet, docker compose in `/opt/field-visits`, app on 127.0.0.1:3000 behind nginx/Let's Encrypt at `https://fieldvisits.164.92.171.41.sslip.io`. Postgres 16 container (`db`, user/db `fieldvisits`). Also in docs: `docs/README.md` index, `docs/governance/*` (architecture, risk register, DoD), `docs/data-model.md`, `docs/roles-permissions.md`, `docs/erp-sync-contract.md`, `docs/lily-integration.md`, `docs/bonuses-design.md`, `docs/offline-sync.md`, `deploy/design-system.md`, `deploy/ui-qa-checklist.md`. Docs say "7 roles / 75 migrations" - outdated; there are 8 roles and ~87 migrations. If docs and code disagree, code wins.

## Stack and shape
- **Server** `server/src`: Node 20+/22, Express 5, ES modules, plain `pg` (no ORM), plain SQL migrations `server/migrations/NNN_name.sql` applied in order by `npm run migrate` (**not** automatically on start - on the droplet run `docker compose run --rm app npm run migrate`). Entry `index.js` (also starts the background jobs: one scheduler, `jobs/index.js`, 18 jobs, state in `background_jobs`, shown in Settings > System health), `app.js` builds the app. One route file per resource in `routes/`. Auth: cookie session (JWT) + CSRF double-submit; helmet; rate limits (bypass for tests via `E2E_RATE_LIMIT_BYPASS_TOKEN`); account lockout; `token_version` invalidates sessions; emergency "lockdown" kill-switch and "calculator mode" (app disguised as a calculator, unlocked by a number combo) in `app_settings`.
- **Client** `client/public`: vanilla JS ES modules, **no build step**, no framework. `index.html`, `js/app.js` (router/shell; views are dynamically imported per route), `js/views/*.js` (one per screen), `js/api.js` (all fetch calls; add new endpoints here), `js/state.js` (current user + role helpers like `canPlanForOthers`), `js/i18n.js` (two dictionaries `en` and `hy`; **every user string needs both**; Armenian is the main language), `js/util.js` (formatters: `formatAmd` whole numbers, tier/category helpers & icons, search matcher), `js/icons.js`, `js/regionTree.js` (shared tri-state accordion bottom-sheet picker), `js/offlineQueue.js` (IndexedDB write queue for check-ins/orders, idempotent client_ref, "needs attention" state), `js/listCache.js` + `productCatalog.js` (per-user cached lists for instant tab switches; cleared on logout/role change), `js/updateBanner.js` (+ Settings "Check for updates"), `css/*.css`, `sw.js` (service worker: CACHE_VERSION, app-shell list, network-first for API/manifest, tile cache).
- **When adding a new JS/CSS file** it must be listed in `sw.js` APP_SHELL and (for CSS) in `index.html`; `npm run verify:ui` and `check:version` catch some omissions.
- Map: Leaflet + OSM/CartoDB tiles, optional OSRM routing (falls back to haversine; compose has an unfetchable `osrm` service - build/start app with `--no-deps`).

## Roles (8)
`admin` (superset), `ceo`, `operations_director` (= CEO permissions), `sales_director` (also has warehouse permissions + can mark delivered without route), `sales_manager` (own data only; sees only customers assigned to them and ERP data for those), `warehouse_manager`, `delivery_manager`, `accountant`. `canConfirmOrders` = admin/sales_director/ceo/operations_director. `canManageProducts` = admin/ceo/accountant.

## Navigation, files, performance (client)
- Back stack in `app.js`: DOM of the last screens is kept (5; 10 on iPhone/iPad via `IS_IOS`; only one Map). Tab switch clears it. `handleNavTap`: tapping the ACTIVE bottom/side tab scrolls to top, a second tap within 1 s restarts the tab (`render()`); other tabs navigate.
- `util.saveBlob` shares files via the native sheet; when iOS refuses `navigator.share` (user gesture used up by the await) it shows `offerFileShare` (in-app sheet, Share + Close) instead of opening the file full-screen in the PWA with no way back. `util.openInfoPopup(html)` = the "!" info popup (sheet with X). Never `window.open`/navigate to a file URL inside the PWA.
- Render safety net in `app.js` (`render()` try/catch + Reload card, 8 s blank watchdog, recovery on visibility/pageshow, one auto-reload on module import failure); Leaflet loader `leafletLoader.js` (per-step markers, 20 s timeout).
- Generic `.card:active` shrinks/fades the card; for a card that only CONTAINS tappable children (route plan rep card) override it, or the whole section "presses" (`.route-plan-rep-card:active`).
- Customer card action row (`.detail-actions-grid`): ONE row, `--action-cols` = 4 or 5, font `clamp(...)`; verified no overflow at 360/390/430 px in Armenian.
- PERFORMANCE RULE: per-customer check-in facts (last visit, visited today/week, overdue) come from ONE lateral aggregate `VISIT_STATUS_JOIN` (alias `v`) in `customers.js`, never from correlated `max(timestamp)` subqueries (they walked the global timestamp index: ~1 s per 3,000 customers). Migration 094 adds `checkins(customer_id, timestamp DESC)`. Route Plans planner uses the light `GET /visit-plans/rules/customers`. Known remaining heavy payloads: `/api/customers` (full list for Map/Customers), `/api/reports/checkins` (2.6 MB) and `/new-customers` (1.3 MB) unbounded, `/visit-plans/team-today` on admin Home, i18n.js 184 KB + styles.css 272 KB at startup.

## Conventions that matter
- Money is AMD, shown with `formatAmd` as whole numbers (no decimals), thousands separators.
- Dates: Yerevan timezone helpers (`yerevanDate.js`, `workingDays.js`); watch week/month boundaries (Mon-start weeks; "this week/month" means calendar period, not last 7/30 days).
- Names are never keys: ERP matching is by `erp_customer_id` / product `erp_product_id`.
- List endpoints paginate; the owner raised limits (sales up to 10 000, activity 1000) - do not re-lower.
- Bottom sheets (`activateDialog`) trap focus, close on Escape/backdrop, restore focus; swipe-back must close only the top-most sheet.
- Touch targets >= 44 px; focus ring thin; icon buttons need aria-labels; 320 px width + long Armenian text must not overflow.
- DB changes = new numbered migration, backward compatible; mention "run migrations" in deploy notes.

## Lists at scale (1.373.0, owner decision 2026-10-19: "500 per page so the app feels no slower")
`GET /api/customers` takes `limit` (max 1000) with `after_name` + `after_id` (keyset on `(name, id)`, index `customers_name_id_idx`) or `offset`; no `limit` = the whole list (Map, route planning). The Customers screen (`views/customers.js load()`) paints page 1 (500) at once and streams the rest behind it; a cached list that is showing is not replaced until every page is in. Pickers pass `limit` equal to what they show (30/30/8). Compute list-wide values with ONE grouped query (see `reserved_qty` in `routes/products.js`, "overdue" in `routes/dashboard.js`), never a correlated subquery per row. To measure: seed a throwaway database (`fv_scale`: 40k customers, 5k products, 600k ERP lines, 100k orders, 200k check-ins), run the app on another port, log queries over 60 ms (`ALTER DATABASE ... SET log_min_duration_statement`) and `EXPLAIN (ANALYZE, BUFFERS)`. Findings and the single-company limits: `docs/scaling.md`. Never `pgrep -f`/`pkill -f` to stop the test server (it matches your own shell): find it by port.

## Pause / offboard a rep (1.376.0, migration 135)

- `users.status` = `active | paused | offboarded` (+ `status_changed_at/by`, `status_note`). The account is never deleted for a real rep: history stays.
- `requireAuth` rejects any non-active user (401) and login answers 403 `account_inactive` after a correct password. Switching off bumps `token_version` (all devices signed out) and deletes `push_subscriptions`.
- Every query that lists reps for pickers, leaderboards, plans, Vaghinak, scorecards, task assignees and debt-task owners filters `status = 'active'`. **When you write a new "list the reps" query, add `AND status = 'active'`.** Historical joins (who made this order) must NOT filter.
- `GET /api/users/:id/offboarding` = checklist (customers by region, open tasks, cash not handed over, orders in progress, plan rules, candidate heirs). `POST /api/users/:id/status {status, note, moves:[{region,to_user_id}], tasks_to_user_id}` hands customers over region by region, open tasks follow their customer, then switches the account. `status:'active'` switches back on (no hand-over in that call).
- UI: Settings -> Team -> person -> "Pause / switch off…" (`openOffboardSheet` in `views/admin.js`), badge "Paused" / "Left" in the list. Tests: `userOffboarding.test.js`, `offboard-rep.spec.mjs`.
- Cash held by the person stays on them until handed over in Cash handoffs (the senders list is deliberately not filtered).
