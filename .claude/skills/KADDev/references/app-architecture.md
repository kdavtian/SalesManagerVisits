# Field Visits app - architecture map

Repo `kdavtian/SalesManagerVisits`. Production: one DigitalOcean droplet, docker compose in `/opt/field-visits`, app on 127.0.0.1:3000 behind nginx/Let's Encrypt at `https://fieldvisits.164.92.171.41.sslip.io`. Postgres 16 container (`db`, user/db `fieldvisits`). Also in docs: `docs/README.md` index, `docs/governance/*` (architecture, risk register, DoD), `docs/data-model.md`, `docs/roles-permissions.md`, `docs/erp-sync-contract.md`, `docs/lily-integration.md`, `docs/bonuses-design.md`, `docs/offline-sync.md`, `deploy/design-system.md`, `deploy/ui-qa-checklist.md`. Docs say "7 roles / 75 migrations" - outdated; there are 8 roles and ~87 migrations. If docs and code disagree, code wins.

## Stack and shape
- **Server** `server/src`: Node 20+/22, Express 5, ES modules, plain `pg` (no ORM), plain SQL migrations `server/migrations/NNN_name.sql` applied in order by `npm run migrate` (**not** automatically on start - on the droplet run `docker compose run --rm app npm run migrate`). Entry `index.js` (also starts `setInterval` jobs: overdue reminders, stale-packed reminders, ERP-sync staleness monitor, daily summary, bonus worker), `app.js` builds the app. One route file per resource in `routes/`. Auth: cookie session (JWT) + CSRF double-submit; helmet; rate limits (bypass for tests via `E2E_RATE_LIMIT_BYPASS_TOKEN`); account lockout; `token_version` invalidates sessions; emergency "lockdown" kill-switch and "calculator mode" (app disguised as a calculator, unlocked by a number combo) in `app_settings`.
- **Client** `client/public`: vanilla JS ES modules, **no build step**, no framework. `index.html`, `js/app.js` (router/shell; views are dynamically imported per route), `js/views/*.js` (one per screen), `js/api.js` (all fetch calls; add new endpoints here), `js/state.js` (current user + role helpers like `canPlanForOthers`), `js/i18n.js` (two dictionaries `en` and `hy`; **every user string needs both**; Armenian is the main language), `js/util.js` (formatters: `formatAmd` whole numbers, tier/category helpers & icons, search matcher), `js/icons.js`, `js/regionTree.js` (shared tri-state accordion bottom-sheet picker), `js/offlineQueue.js` (IndexedDB write queue for check-ins/orders, idempotent client_ref, "needs attention" state), `js/listCache.js` + `productCatalog.js` (per-user cached lists for instant tab switches; cleared on logout/role change), `js/updateBanner.js` (+ Settings "Check for updates"), `css/*.css`, `sw.js` (service worker: CACHE_VERSION, app-shell list, network-first for API/manifest, tile cache).
- **When adding a new JS/CSS file** it must be listed in `sw.js` APP_SHELL and (for CSS) in `index.html`; `npm run verify:ui` and `check:version` catch some omissions.
- Map: Leaflet + OSM/CartoDB tiles, optional OSRM routing (falls back to haversine; compose has an unfetchable `osrm` service - build/start app with `--no-deps`).

## Domains and where they live (server route -> client view)
- Customers: `routes/customers.js` (list is client-side filtered in `views/customers.js` `applyNonStatusFilters`; tiers; edit-request approval flow; erp link; region/subregion; social profiles `customerSocial.js`; sales channel autofill `salesChannelAutofill.js`, `route_distribution`) -> `customers.js`, `customerDetail.js`, `customerPortfolioUi.js`.
- Check-ins (GPS radius check, photos, offline duplicates): `checkins.js` -> `checkin.js`, `visitDetail.js`, activity tab `activity.js`.
- Orders: `orders.js` (state machine draft -> submitted -> confirmed -> packed_stock_out -> delivered, plus rejected/cancelled; discount approval; items edit; accounting request/signed), `orderMeta.js`; client `orders.js`, `orderCreate.js`, `orderDetailSheet.js`, `accountingDocSheet.js`, `customerOrders.js`. Pricing: `tierPricing.js` (tier list price), `pricingService.js` (promos), snapshot at save time in `buildOrderLines`.
- Warehouse/delivery: `warehouse.js`, `delivery.js`, `routeDistribution.js` -> `warehouse.js`, `deliveryRoute.js`. Stock forecast `stockForecast.js` (days of stock left: <45 critical, 45-90 low, >=90 ok; dead stock).
- Payments & cash: `payments.js`, `cashHandoffs.js`, `cashExpenses.js` -> `payments.js`, `cashHandoffs.js`, `cashExpenses.js`.
- ERP data in app: `erpSync.js` (+`erpTransform.js`, `erpSyncMonitor.js`, `erpSyncFreshness.js`), `debtBalances.js`, `sales.js`, `reports.js`/`exports.js`, `dataQuality.js`, `salesPerformance.js`, `teamPerformance.js` -> `debtBalances.js`, `sales.js`, `reports.js`, `teamPerformance.js`, `dashboard*.js`.
- Notifications/push: `notifications.js`, `push.js`, `notificationPreferences.js`, `telegram.js` (admin alerts) -> `notifications.js`, `pushNotifications.js`.
- Bonuses (feature-flag `app_settings.bonuses_enabled`, `quick_action_visibility`): many `bonus*.js` services + `routes/bonus*.js` -> `bonuses.js`, `bonusChallengesAdmin.js` (admin wizard). Design in `docs/bonuses-design.md`.
- Lily accountant integration: `integration.js` (`/api/integration/v1`, bearer token, test-mode tokens only see `accounting_is_test` orders), `integrationAdmin.js`, `integrationTokens.js` (SHA-256 stored), `accountingStatus.js`, `scripts/integration-token.mjs create "<name>" [--test]`. Statuses: pending -> in_progress -> waybill_created|partially_created -> exported_unsigned -> signed, plus needs_attention. DB rule: `accounting_doc_type` waybill only with cash, invoice only with invoice (migration 086).
- Users/roles: `users.js`, `auth.js`, `roles.js` (central capability functions - always add new permissions there, with a unit test in `test/roles.test.js`).
- Admin: Settings -> Admin workspace (`views/admin.js`, `settings.js`): users, products/pricing, lockdown, calculator mode, bonuses, integration tokens, data quality, error log.

## Roles (8)
`admin` (superset), `ceo`, `operations_director` (= CEO permissions), `sales_director` (also has warehouse permissions + can mark delivered without route), `sales_manager` (own data only; sees only customers assigned to them and ERP data for those), `warehouse_manager`, `delivery_manager`, `accountant`. `canConfirmOrders` = admin/sales_director/ceo/operations_director. `canManageProducts` = admin/ceo/accountant.

## Tests and checks
- `cd server && npm test` = node:test unit + integration (real Postgres; helpers in `test/integration/helpers.js`: `startTestServer`, `createUser(role)`, `createCustomer`, `createProduct`, `loginAs`, `apiRequest`, `trackOrder`, `cleanupAll`). Test users use emails `itest-*@kadmotors.local` - ensure cleanup so they do not pile up in prod (owner complained). Known flake: cross-file parallelism (e.g. `orderLifecycle` notification FK, `bonusReconciliation`, erp-sync daily-report coalescing) - one CI re-run is allowed; do not disable.
- `npm run verify:ui` (static invariants, ~26 checks), `npm run check:version` (CHANGELOG/package.json), `npm run test:e2e[:smoke]` Playwright (specs in `server/test/e2e`, CI job `e2e-smoke`), nightly e2e workflow.
- CI (`.github/workflows`): jobs `test` and `e2e-smoke`; CODEOWNERS and PR template exist (`.github/pull_request_template.md` - mirror its headings in PR bodies).

## Conventions that matter
- Money is AMD, shown with `formatAmd` as whole numbers (no decimals), thousands separators.
- Dates: Yerevan timezone helpers (`yerevanDate.js`, `workingDays.js`); watch week/month boundaries (Mon-start weeks; "this week/month" means calendar period, not last 7/30 days).
- Names are never keys: ERP matching is by `erp_customer_id` / product `erp_product_id`.
- List endpoints paginate; the owner raised limits (sales up to 10 000, activity 1000) - do not re-lower.
- Bottom sheets (`activateDialog`) trap focus, close on Escape/backdrop, restore focus; swipe-back must close only the top-most sheet.
- Touch targets >= 44 px; focus ring thin; icon buttons need aria-labels; 320 px width + long Armenian text must not overflow.
- DB changes = new numbered migration, backward compatible; mention "run migrations" in deploy notes.
